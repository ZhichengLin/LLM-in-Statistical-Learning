# Learning statistical concepts with generative AI: evidence from longitudinal, randomized source-label experiments

Data, code, materials, and outputs for a two-study investigation of learning
statistical concepts from generative-AI explanations. Study 1 benchmarked 15
LLMs on 17 true/false items about P values, confidence intervals, and comparisons
across studies; blinded instructors and students then rated selected
explanations. Study 2 held the selected explanations constant while randomly
describing them as AI, AI + Human, or Human, and assessed learning within the
session, at one month, and in an exploratory follow-up about 14 months later.

The long-term follow-up extends the evidence beyond immediate performance:
the 33 eligible participants with both follow-ups scored 13.6 percentage points
above baseline at 14 months (95% CI 4.3–23.0; Holm-adjusted P = .012), while
scoring below the end-of-session level. This is longitudinal evidence of
retention among returners. Randomized source descriptions identify effects of
source attribution over identical explanations in the original experiment;
the long-term within-person change, without an untrained control and with
substantial attrition, does not establish a causal effect of instruction or a
sustained causal advantage of any label.

Study 2 [withheld for anonymous review]. The 14-month analyses
were not preregistered. Selection of the both-follow-up primary sample and

## What this repository reproduces

The current mapping uses `Main v2.docx` and `SI v2.docx`, verified on 2026-10-03.
Main contains Figures 1–6 and no numbered tables; its Supporting Information
(SI) contains Texts S1–S5, Fig. S1, and Tables S1–S24.
The crosswalk in [`MANUSCRIPT_OUTPUT_MAP.md`](MANUSCRIPT_OUTPUT_MAP.md) connects
each computational result to its source, input, and generated output. The
authoring DOCX files are not deposited. Stable links to the published article
and SI will be added when available.

Running the complete workflow regenerates the deposited initial-session and
one-month analyses, the new 14-month analyses and supplementary table exports,
and code-generated Figs. 3–6 and S1. Final static versions of
Figs. 1 and 2 are included as visual records; they are not generated by the R
workflow, but the root runner verifies their presence and SHA-256 hashes.

The deposited Study 2 analysis inputs begin with the 178 records that passed
completion and attention screening. They reproduce the three ceiling
exclusions and the resulting analytic samples of 175 initially and 84 at
follow-up. The earlier flow from 220 randomized participants to 178 screened
records cannot be recalculated because the abandoned and attention-check-fail
records are not available. This upstream boundary does not prevent readers
from reproducing the analyses reported for the deposited cohorts.

The long-term module deposits analysis-ready pseudonymous data: 44 returns,
five excluded for reported external assistance, 39 eligible returners, and a
primary sample of 33 with both follow-ups (AI 16, AI + Human 10, Human 7).
The full-cohort continuation omits all waves of the five excluded participants
and uses 170 participants, or 168 with complete covariates. The original
175/84 analyses remain unchanged historical analyses. Eligibility is based on
self-report; it is not proof that answering was unaided.

## Quick start from a clean copy

Requirements:

- R 4.5.1, matching both package lockfiles
- Python 3 for long-term validation and supplementary table exports
- Pandoc (included with RStudio or installed separately)
- a compiler toolchain and gettext development libraries if a locked package
  is unavailable as a prebuilt binary
- macOS Quartz and Helvetica for exact reproduction of the current Figure 5/6
  PDFs; the other figure sources use their recorded graphics devices

Open the [anonymous repository](https://anonymous.4open.science/r/statistical-learning-6703/), choose **Download ZIP**, and extract the archive. From the extracted repository root, run:

```sh
shasum -a 256 -c SHA256SUMS
Rscript -e 'renv::restore(project = ".", library = renv::paths$library(project = "."), prompt = FALSE)'
Rscript -e 'renv::restore(project = "Study_2_LongTerm_Results", library = renv::paths$library(project = "Study_2_LongTerm_Results"), prompt = FALSE)'
Rscript reproduce.R all
```

The checksum command verifies the deposited snapshot before restoration or
analysis modifies generated records.

Restore both environments before running `all`. Each command explicitly names
the target project’s library; a project argument alone can otherwise select
the currently active library. The original lockfile retains
its 200 recorded package versions; the long-term lockfile records the 144
packages for the executed extension and current Figure 5/6 code. This includes
the six optional startup namespaces recorded in the executed source session,
preserving their package and method availability. The runner
selects the environment for each task and does not install or update analysis
packages. Activation can bootstrap pinned `renv` infrastructure if absent;
restore both environments before running.
The complete workflow is CPU-intensive and can take several hours, depending
on hardware and model fitting. macOS arm64 users who encounter a
source-compilation failure should consult [`SETUP_MACOS.md`](SETUP_MACOS.md).

After a complete restore, `renv::status()` may still report the project as
out-of-sync because `ggrepel`, `showtext`, `showtextdb`, and `sysfonts` are
recorded and installed but are not currently referenced by the analysis code.
An unused-package warning differs from a missing or mismatched locked version,
which must be resolved before claiming exact environment reproduction. All 200
original versions matched in the previously verified original environment; this
historical check does not certify the extension.

The runner accepts three profiles:

```sh
Rscript reproduce.R list  # list the ordered entry points without running them
Rscript reproduce.R core  # central analyses and code-generated figures
Rscript reproduce.R all   # every mapped analysis, sensitivity check, and figure
```

Use `all` to regenerate the mapped computational outputs for the manuscript
and SI. It executes every task in a fresh R process, supplies the correct
working directory, and checks that each declared output exists and was
refreshed. It also removes an unused dangling
drawing/VML relationship defect produced by the locked `openxlsx` version and
validates the internal relationships of every generated XLSX archive, allowing
strict as well as tolerant spreadsheet readers to open the outputs. Before
rendering an R Markdown file, the runner removes only that task's ignored
knitr cache directories so a prior cache cannot make a stale workbook appear
current.

The long-term task validates the deposited manifest, schema, sample
relationships, QC fixtures, and bound readiness record before fitting models.
It runs independent numerical and membership checks afterward. Readiness
covers the deposited analysis-ready inputs and stated estimands; it does not
reconstruct private linkage or historical study administration.

The supported route is the root runner, which resolves paths from its own
location. Individual notebooks intentionally use folder-relative paths; run
them only after activating their required environment and setting the named
analysis folder as the working directory.

## Interpretation of the long-term outputs

Primary long-term accuracy gives each task equal weight: the mean of the
six-item, five-item, and six-item task accuracies. The 17-item weighted result
is a separately labeled sensitivity analysis. For continuity with earlier
artwork, Figs. 5–6 use the original overall 17-item accuracy/confidence scores
and available samples of 175/84/33. Their connecting lines do not represent
matched within-person changes. Paired estimates are in
`Study_2_LongTerm_Results/results/paired_contrasts.csv`.

The primary paired one-month-to-14-month accuracy change is +0.8 percentage
points (95% CI −6.7 to 8.3; Holm P = .828). The full-cohort unadjusted MAR GLS
estimates +7.0 points (95% CI 0.4–13.6; Holm P = .038). These estimates target
different populations and depend on different missing-data assumptions;
neither a nonsignificant paired test nor similarity of means establishes
stability or equivalence.

Two model qualifications remain explicit in the deposited diagnostics and
SI Table S24. The unadjusted full-cohort accuracy GLS lacks a usable `apVar`
matrix and uses residual df = 599. The covariate-adjusted task-structured
confidence model has a singular `ID:Task` variance of zero and is retained as
a sensitivity diagnostic, not used for the main confidence conclusions.
Numerical agreement does not remove these model qualifications.

## Output and data conventions

- **Manuscript-generating analyses:** Study 1 objective/subjective notebooks,
  Study 2 H1/H2 models, follow-up models, correction timing, and Figs. 3–6/S1.
- **Robustness and sensitivity:** task-structured, item-level,
  manipulation-recall, perceived-label, completer-only, and
  attrition-adjusted models.
- **Exploratory:** correction timing, multiplicity-corrected moderation, and
  every 14-month analysis. The original 175/84 analyses and extended
  33/39/170/168 analyses remain separately labeled.
- **Diagnostics:** model-specification comparisons, singular-fit diagnostics,
  attrition comparisons, and demographic balance.
- **Static/materials targets:** Main Figs. 1–2, instruments, rubric, and
  manually curated metadata tables.

Some SI tables are printed in rendered HTML rather than exported as separate
table-shaped workbooks. The crosswalk identifies these cases. Source R/Rmd and
analysis-ready input files are the computational authority; generated HTML,
workbooks, and figures are retained as reader-friendly records.

The self-contained folders deliberately contain a few synchronized data
copies so individual analyses can run with local paths. Their relationships
are documented in [`DATA_DICTIONARY.md`](DATA_DICTIONARY.md). Do not treat these
intentional copies as independent samples.

## Reproducibility boundaries

The repository supports the analyses beginning from the deposited,
analysis-ready inputs. It does not reconstruct:

- raw survey-platform or model-service exports;
- the 220→178 completion and attention-screening flow;
- private participant/email linkage, two unmatched long-term submissions,
  complete historical platform delivery, or invitation/consent/ethics records;
- manually authored Figs. 1 and 2 from code; or
- editorial assembly of the Main and SI documents.

The manuscript-to-output map labels each affected target. These are source-data
or authoring boundaries, not failures of the deposited analysis workflow.

Participant and rater keys are pseudonymous numeric identifiers required to
link repeated observations. The long-term public derivative preserves
historical outcomes and eligible long-term observations. Long-term outcomes
and auxiliary responses for the five excluded returners are suppressed; an
explicit return flag preserves the 44→5→39 sample flow. Intervals are deposited
for the 39 eligible returners as elapsed days rounded to 0.1 day, without
calendar dates. This rounding preserves all reported one-decimal interval
summaries and affects no inferential-model input.

The deposited inputs contain no participant names, email addresses, telephone
numbers, postal addresses, IP addresses, exact submission timestamps, or
identity crosswalk. Pseudonymous repeated-measures data are not claimed to be
anonymous.
