# Source labels change the timing of accuracy gains with identical AI-generated explanations of statistical concepts

Data, code, materials, and outputs for a two-study investigation of how source
labels change learning from fixed LLM-generated explanations of statistical
concepts.

Study 1 benchmarked 15 LLMs on 17 true/false items covering P-value
interpretation, confidence-interval interpretation, and comparison of results
across studies. Blinded instructors and students then evaluated explanations
from the two highest- and two lowest-performing models. Study 2 held the
selected explanations constant while randomly describing them as AI, AI +
Human, or Human across a three-stage learning sequence and a follow-up
approximately one month later.

Preregistrations: Study 1 [osf.io/5jwtk](https://osf.io/5jwtk/overview) and
Study 2 [osf.io/daphw](https://osf.io/daphw/overview).

Repository: [github.com/ZhichengLin/LLM-in-Statistical-Learning](https://github.com/ZhichengLin/LLM-in-Statistical-Learning)

## What this repository reproduces

The manuscript version mapped for this release contains Figures 1–6 and no
numbered tables; its Supporting Information (SI) contains Texts S1–S4, Fig. S1,
and Tables S1–S21.
The crosswalk in [`MANUSCRIPT_OUTPUT_MAP.md`](MANUSCRIPT_OUTPUT_MAP.md) connects
each computational result to its source, input, and generated output. The
authoring DOCX files are not deposited. Stable links to the published article
and SI will be added when available.

Running the complete workflow regenerates the analyses supporting the reported
statistics and the code-generated Figs. 3–6 and S1. Final static versions of
Figs. 1 and 2 are included as visual records; they are not generated by the R
workflow, but the root runner verifies their presence and SHA-256 hashes.

The deposited Study 2 analysis inputs begin with the 178 records that passed
completion and attention screening. They reproduce the three ceiling
exclusions and the resulting analytic samples of 175 initially and 84 at
follow-up. The earlier flow from 220 randomized participants to 178 screened
records cannot be recalculated because the abandoned and attention-check-fail
records are not available. This upstream boundary does not prevent readers
from reproducing the analyses reported for the deposited cohorts.

## Quick start from a clean copy

Requirements:

- R 4.5.1, matching `renv.lock`
- Pandoc (included with RStudio or installed separately)
- a compiler toolchain and gettext development libraries if a locked package
  is unavailable as a prebuilt binary
- Helvetica and a Cairo-capable graphics stack for typography matching the
  deposited figures

Open a terminal in the repository root and run:

```sh
git clone https://github.com/ZhichengLin/LLM-in-Statistical-Learning.git
cd LLM-in-Statistical-Learning
Rscript -e 'renv::restore(prompt = FALSE)'
Rscript reproduce.R all
```

Before running the analyses, you can verify the deposited release snapshot with
`shasum -a 256 -c SHA256SUMS`.

The `renv::restore(...)` command restores the package versions recorded in
`renv.lock`.
`reproduce.R` does not install or update packages. The complete workflow is
CPU-intensive and may take well over an hour on a laptop; the follow-up mixed
models dominate the runtime. macOS arm64 users who encounter a
source-compilation failure should consult [`SETUP_MACOS.md`](SETUP_MACOS.md).

After a complete restore, `renv::status()` may still report the project as
out-of-sync because `ggrepel`, `showtext`, `showtextdb`, and `sysfonts` are
recorded and installed but are not currently referenced by the analysis code.
This expected unused-package warning is not a restore failure: all 200 package
versions recorded in `renv.lock` matched in the verified environment.

The runner accepts three profiles:

```sh
Rscript reproduce.R list  # list the ordered entry points without running them
Rscript reproduce.R core  # central analyses and code-generated figures
Rscript reproduce.R all   # every mapped analysis, sensitivity check, and figure
```

Use `all` to verify the manuscript and SI. It executes every task in a fresh R
process, supplies the correct working directory, and checks that each declared
output exists and was refreshed. It also removes an unused dangling
drawing/VML relationship defect produced by the locked `openxlsx` version and
validates the internal relationships of every generated XLSX archive, allowing
strict as well as tolerant spreadsheet readers to open the outputs. Before
rendering an R Markdown file, the runner removes only that task's ignored
knitr cache directories so a prior cache cannot make a stale workbook appear
current.

The supported route is the root runner. If you need to inspect a single
notebook interactively, first restore and activate the project from the root,
then use the analysis folder as the notebook's working directory. For example,
from the repository root:

```sh
Rscript -e 'setwd("Study_2_Main_Results"); rmarkdown::render("Study 2 Main Results.Rmd")'
```

The folder-relative paths inside the notebooks are intentional. Running a
notebook from an unrelated working directory can send outputs to the wrong
location; the root runner avoids that ambiguity.

## Output and data conventions

- **Manuscript-generating analyses:** Study 1 objective/subjective notebooks,
  Study 2 H1/H2 models, follow-up models, correction timing, and Figs. 3–6/S1.
- **Robustness and sensitivity:** task-structured, item-level,
  manipulation-recall, perceived-label, completer-only, and
  attrition-adjusted models.
- **Exploratory:** correction timing and multiplicity-corrected moderation.
- **Diagnostics:** model-specification comparisons, singular-fit diagnostics,
  attrition comparisons, and demographic balance.
- **Static/materials targets:** Main Figs. 1–2, instruments, rubric, and
  manually curated metadata tables.

Some SI tables are printed in rendered HTML rather than exported as separate
table-shaped workbooks. The crosswalk identifies these cases. Source R/Rmd and
analysis-ready input files are the computational authority; generated HTML,
workbooks, and figures are retained as reader-friendly records.

The self-contained folders deliberately contain a few synchronized data
copies so individual analyses can run with local paths. Their relationships
are documented in [`DATA_DICTIONARY.md`](DATA_DICTIONARY.md). Do not treat these
intentional copies as independent samples.

## Reproducibility boundaries

The repository supports the analyses beginning from the deposited,
analysis-ready inputs. It does not reconstruct:

- raw survey-platform or model-service exports;
- the 220→178 completion and attention-screening flow;
- manually authored Figs. 1 and 2 from code; or
- editorial assembly of the Main and SI documents.

The manuscript-to-output map labels each affected target. These are source-data
or authoring boundaries, not failures of the deposited analysis workflow.

Participant and rater keys are pseudonymous numeric identifiers required to
link repeated observations. The deposited inputs contain no participant names,
email addresses, telephone numbers, postal addresses, IP addresses, exact
submission timestamps, or identity crosswalk.
