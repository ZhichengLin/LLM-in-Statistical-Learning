# macOS arm64 setup

The ordinary installation command is sufficient when compatible R package
binaries are available:

```sh
Rscript -e 'renv::restore(project = ".", library = renv::paths$library(project = "."), prompt = FALSE)'
Rscript -e 'renv::restore(project = "Study_2_LongTerm_Results", library = renv::paths$library(project = "Study_2_LongTerm_Results"), prompt = FALSE)'
```

The explicit `library` arguments direct each restore to the named project’s
library instead of relying on the library currently active in R.

The nested `renv/activate.R` uses the bootstrap template generated by the
root `renv` 1.2.3 restore, while selecting the nested lockfile's `renv` 1.1.7.
Restoring the nested project through a different `renv` version can rewrite
this infrastructure file; use the documented root commands above.

The original verified environment used macOS arm64, R 4.5.1, Pandoc 3.6.3, GNU Fortran
14.2, GNU gettext 0.22.5, Helvetica, and Cairo-capable graphics. The R package
versions are recorded in `renv.lock`; compilers, system libraries, Pandoc, and
fonts are outside `renv`. The 14-month extension and current Figure 5/6 code
have their own lockfile at `Study_2_LongTerm_Results/renv.lock`; both environments
must be restored. The root runner selects the appropriate environment for
each task. Python 3 is also required for the extension's QC and aggregate
table exports.

## If restoration requires source compilation

1. Install R 4.5.1 for arm64 and the matching GNU Fortran 14.2 toolchain from
   the official [R for macOS tools page](https://mac.r-project.org/tools/).
2. Install the Xcode Command Line Tools:

   ```sh
   xcode-select --install
   ```

3. Install GNU gettext development headers and libraries. The verified host
   used the official R for macOS gettext 0.22.5 bundle; an equivalent arm64
   installation may also work.
4. Start a new terminal, return to this repository root, and run the ordinary
   restoration command again.

Useful checks are:

```sh
R --version
pandoc --version
xcrun --sdk macosx --show-sdk-path
gfortran --version
```

Do not update individual R packages after restoration: the analysis should use
the versions in `renv.lock`. If a build still fails, preserve the complete
error output; the first missing compiler, header, or library named there is
usually the actionable system dependency.

## Current Figure 5/6 PDF export

The approved PDFs use native macOS Quartz to preserve fractional Helvetica
glyph advances. Their Rmd sources stop if Quartz is unavailable rather than
silently substitute a different PDF device. Helvetica regular, bold, and
oblique must be available. PNG/SVG exports retain their existing devices.

This is a graphics requirement for reproducing the deposited Figure 5/6
artwork. Numerical analyses do not require Quartz, but the complete `all`
profile includes those PDFs and therefore requires the supported macOS
graphics environment. A different PDF device or font would need separately
validated artwork and cannot be described as exact visual reproduction.

## Verification boundary

The original full workflow was verified on macOS arm64. Other operating systems may
require equivalent compiler and gettext development packages, and font
substitution may cause small visual differences even when numerical outputs
match. Full release verification requires the complete `all` workflow in a
clean clone after restoring both pinned environments. Record the tested
commit, system and package environments, exit status, output comparisons,
and retained qualifications in the release notes. The supported entry points
resolve paths from the repository and do not require private scratch inputs.
